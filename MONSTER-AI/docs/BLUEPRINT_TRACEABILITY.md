# Blueprint traceability

This document maps every requirement of the MONSTER AI design blueprint (version 1.0, 31 October 2026) to the code that implements it, the tests that cover it and its **current** status. The first build was audited against the blueprint section by section; the defects found were fixed, and every row below was then re-checked against the code as it stood on 2026-11-01, after the last fix cycle. It is a status record, not a sales document: a row is marked ✅ only when a code path and an automated test exist.

**How to read it.** Sections follow the blueprint numbering (§1-§25, Appendix A, Appendix B). Row ids `N.k` are stable references. "Implemented in" gives links relative to `docs/` plus function or class names in code spans (never line numbers, which drift). "Tests" names the files under `tests/`. A note that starts with "Not built" means the blueprint item does not exist in the code at all; every such row is marked ⚠️ because the legend has no separate symbol for it.

**Legend**

| Symbol | Meaning |
|---|---|
| ✅ | implemented and tested |
| 🔧 | implemented after the audit (found missing/wrong, now fixed) |
| ⚠️ | partial / known limit (stated) |
| 🔀 | deliberate deviation (reason given) |

| Prefer licensed, timestamped feeds; exchange or broker data (§2, §3, B.2) | Public NSE archives and API, unofficial Yahoo through curl_cffi with browser impersonation, RSS, GDELT, optional FRED; licence and failure notes per source in [DATA_SOURCES.md](DATA_SOURCES.md) | The blueprint itself allows research feeds for prototyping; no licensed feed was available | Shadow research only: endpoints can change or block without notice and commercial use needs a licensed feed |
| XGBoost, CatBoost, FinBERT, sentence embeddings (§13, §6) | LightGBM only; rule-based classification with optional LLM extraction; lexical clustering (simhash, TF-IDF) | A 1 GB server cannot host heavy NLP models, and the blueprint says to add them only if they show out-of-sample value | Paraphrased re-reports can count as independent sources; no learned sentiment; no cross-library model comparison |
| Intraday measures: VWAP, intraday relative volume, volume acceleration, time to extreme (§7, §10, §12, Appendix A) | Daily-bar proxies: typical-price distance, `t_rvol1 - t_rvol5`; no time-to-extreme or reversal features | No intraday or tick history is available from the free sources; the 5-minute reader has no caller | Coarser features; the official `vwap` column is stored but unused |
| systemd with APScheduler or cron (§16) | In-house ledger-based scheduler daemon under systemd | The ledger gives catch-up after a reboot, no double runs and visible missed jobs, which a tick-based cron cannot | More code to maintain; `TRAINING_DOW` and the scan-time settings do not move the fixed timetable |
| Docker among the deployment artefacts (§21) | Native systemd units and a shell installer; no Docker or Podman | Operator decision: no container tooling (the blueprint also advises against containers on the smallest server) | A test asserts that no container tooling is shipped |
| Historical storage off the server (§16) | A bounded local SQLite file with per-table retention windows and a data budget; S3-compatible storage only for backups and model bundles | One consistent store is simpler, and retention keeps it inside its budget | Disk is the limit; history beyond the windows is dropped, not archived |
| Production should not train; external worker publishes signed artifacts (§16) | External signed-bundle training is supported; the default `TRAINING_MODE` is `local-light` with a lean profile | Works out of the box without a cloud account | A server without S3 settings trains on the box |
| Autonomous order placement is out of scope; research executable rules separately (§1, §13) | Shadow-only: no order, broker or execution-simulator code | Matches the blueprint's initial scope | No net-of-cost execution evidence exists; MFE and MAE are descriptive only |

## Known limits and residual risks

- Linux, systemd and the installer are validated only statically on a Windows machine (structure tests, shellcheck); nothing was run on a Linux server and a reboot was never exercised.
- The NSE pre-open parser is tested on recorded fixtures only and has never seen a live pre-open session; order imbalance is parsed and stored but used nowhere.
- No 1 GB RAM soak or load test was run; the 660 MB peak was measured on a Windows PC and there is no CPU or load metric.
- News features (`ev_*`, `gl_*`) are not model inputs and reach the report only; `MIN_NEWS_MODEL_DAYS` is an unused setting; no news-only, technical-only or F&O-only baseline exists.
- Graph propagation ignores edge sensitivity, lag and regime; regime betas are stored in `kv` and read by nothing; event time comes only from the optional LLM.
- `Intel.reacted` reads the current `market_reacted` flag, which is right live and wrong for a replay; `t_range_exp` divides by a 20-day mean that includes the measured session.
- `spec_std_p95`, the specialist-disagreement limit, is one global quantile rather than conditional on probability.
- `ingest_fno_day` stores rows only for stocks currently flagged F&O, and a stock that leaves F&O keeps `u_is_fno` = 1.
- Models trained before `fv2` are retired: the scan uses the labelled heuristic baseline until `train` has run once.
- Similar-day parity holds except for the first ~240 rows of a training window, which see a shallower pool.
- Replays read bars by trade date rather than by `received_at`; names this database never ingested and index membership history stay unknown (printed in every backtest report).
- Event typing has gaps: China stimulus and property, PBoC, SEC enforcement, Bank of Korea, energy-supply outages and product recalls come out as `other`.
- The holiday calendar never guesses lunar holidays; until NSE publishes a year's list the final scan confirms the day live. The shipped seed covers 2026.
- `econ_calendar` and FRED first-release data are stored but read by nothing, although the source register says event-day flags default to 0.
- A heavy job waiting for RAM or disk holds back every other due job, and critical jobs cannot preempt each other.
- A transient `OSError` while reading a model artifact retires the champion; only the newest 5 versions per stage are kept; signing is HMAC with a shared key.
- If gpg fails, a plaintext backup is stored and only logged at ERROR.
- Dead or stale code: `MIN_NEWS_MODEL_DAYS`, `TRAINING_DOW`, `fetch_intraday`, the live option-chain reader, five unused exception types, and a `labels.py` docstring that points at a nonexistent `backtesting.execution`; the report says "range >=" while labels use "range >".
- The evening summary's `data_quality_notes` is never filled, and there is no post-hoc attribution.
- Live-record intervals need at least 5 evaluated days and slices at least 5 picks, so they stay empty until days accumulate.
- Host hardening (key-only SSH, updates, firewall) is the operator's job.

## Audit findings that were fixed

**Data and ingestion**
- Official rows (raw) next to split-adjusted vendor rows produced a +400 % fake return after a 5:1 split: official rows are now re-based at read time, exchange-implied splits are repaired after the session, and an ex-date name is scored without its gap.
- Provisional vendor bars were never upgraded to the official file: `ingest_official` runs from the session jobs and housekeeping.
- Rejected bars were dropped silently, including genuine extreme days: now logged, counted per symbol, extreme-but-consistent days kept as `suspect`.
- A vendor reload could leave a half-written series: it now fetches first and replaces the vendor rows in one transaction.
- Training panels held survivors only and `u_is_fno` was today's flag: survivorship-aware panels and a point-in-time F&O flag.
- The universe liquidity window used SQL `date('now')`: now anchored on the IST trading date.
- Monday morning missed Friday's filings: `filings_window` starts before the previous trading session.
- HTTP: curl_cffi with browser impersonation, per-host adaptive rate limits, `Retry-After`, circuit breaker, deadlines and bulk probes (Yahoo spark, RSS conditional GET).
- The holiday calendar lapsed after the seed's last year: layered rules, NSE refresh, inferred closures and overrides, with a 21-day health warning.

**News and graph**
- Edges were overwritten and replays used today's edges: append-only `graph_edge_history`, `edges_as_of`, opt-in `point_in_time_edges`.
- A poison news item was silently lost: bounded retries, then `processed = 2` with an ERROR.
- A known market reaction could be overwritten by "unknown", and an unverified LLM time was kept: both fixed.
- The economic-calendar key included the scheduled time: keyed by country, title and date.
- A broken relationship kept the prior sign: it now asserts no direction, and chains are tagged measured, expert prior or broken.
- Novelty class, rumour flag and source class were not stored or shown: columns plus a provenance tag on each catalyst.
- Mere mentions counted as events and enrichment slots went to ineligible names: subject-only counting and an enrichment pool taken after the gates.

**Features and models**
- Relative volume included the measured session: baseline is now the 20 sessions before it.
- Similar-day features differed between training and live: fixed pool and statistics windows and a sized live history.
- Stale global series were carried forward for ever: blanked after 4 days (7 for Europe and Asia).
- Results dates were treated as known far ahead: `RESULTS_HORIZON = 10`; sector dispersion is leave-one-out.
- The OI contradiction rules could never fire: now compared with the indicated gap or the 5-day trend.
- `FEATURE_VERSION = "fv2"` gates models; the baseline honours `UNUSUAL_K`; Brier skill uses the pre-holdout base rate; version stamps use the UTC clock.
- The disagreement limit was fixed at 0.12: each model supplies its own, and `x_sim_nvalid` reaches the meta-model.
- An unusable champion with nothing to roll back to stayed active: now deactivated.

**Ranking and reports**
- The preliminary "gap" baseline was yesterday's range: `recent_range` and `gap` are separate baselines.
- Catalysts show rumour, source class, independent sources and conflicts; GIFT Nifty appears in the regime line while fresh; ex-date names carry a report note.
- Explainer failures were swallowed silently: logged at WARNING.

**Evaluation**
- Snapshot and predictions were separate commits: one transaction, with repair of an interrupted older freeze.
- A forced re-scan double-counted picks and `rolling_summary` pooled both stages: only effective snapshots are scored, one stage per day.
- The features hash could not be re-verified: it now covers the stored values; every snapshot freezes per-source freshness and a code stamp.
- Intervals ignored day clustering and range-forecast error, NDCG, rank IC, median range and slices were missing or unused: day-block bootstrap and a live record in the evening report, `eval_metrics` and the dashboard.

**Operations and deployment**
- Unbounded growth of events, quotes, metrics and deliveries: `retention.py`, a data budget, a backup budget, VACUUM policy and a `storage` command.
- Size-rotated logs clashed with concurrent processes and logrotate: daily files, crash hooks, redaction, `logs` and `diag` commands.
- A daemon crash was silent and its heartbeat shared the SQLite writer lock: heartbeat file and a `daemon_restarted` alert.
- Critical disk did not block heavy jobs: `_disk_ok` and a `train` precheck; a daily false `stale_bars` alert was removed.
- UTC or naive dates in bootstrap, health, universe and model stamps: IST helpers, a pinned process zone, an AST guard and a five-zone matrix test.

## Keeping this document true

- When a module named in "Implemented in" changes, re-check its rows and update the status and the Summary counts together; a ✅ needs a code path and a test, and links must not use line numbers.
- Tests: `python -m pytest -q -p no:cacheprovider` (or the files named in the row); the machine: `python -m app.cli doctor`; operations: `python -m app.cli health` (exit code 0, 1 or 2) and `python -m app.cli storage`.
- Research rows: `python -m app.cli backtest` writes the benchmark report; `python -m app.cli version` prints the release stamp that every snapshot carries.
- Regenerate [DATA_SOURCES.md](DATA_SOURCES.md) with `python scripts/generate_docs.py` whenever the source register changes.
